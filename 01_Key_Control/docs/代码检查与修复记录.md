## 已修复的问题

| 问题 | 触发条件与影响 | 修改 |
|---|---|---|
| 数据载荷被误当作完成通知 | 实际位置帧为`01 36 00 01 FD 9F 6B 6B`时，原解析器收到前7字节就会把其中的`01 FD 9F 6B`解析为到位，提前结束运动监视 | `zdt_x42s.c`保留最早的合法候选帧，等待固定长度；仅在候选不合法时滑动重新寻找帧头 |
| 慢确认被自动查询覆盖 | FD确认在发送50ms后、100ms期限内返回时，同轮协议处理立即启动3A查询，覆盖应用层尚未处理的FD事务结果；随后查询失败还可能让已接受的运动停留在MOVE_ACK | 自动查询同时检查发送间隔与上一匹配回复间隔，均至少50ms，让应用先消费确认结果 |
| 命令后复用旧状态或串用另一地址的缓存 | F3失能后仍保留旧的已使能状态；FD快速完成后仍可能复用运动前位置；FE切换地址时没有走普通事务的缓存清理路径 | 统一地址选择与缓存失效；F3使能状态、FD运动前状态与位置、FE状态/位置/目标缓存失效；跨地址清理所有相关缓存 |
| 取消版本查询后状态一直等待 | FE抢占等待中的1F查询后，transaction已属于FE，但旧版本state仍是WAIT_RESPONSE | 将被取消的版本查询置为ERROR，保留取消计数与会话恢复要求 |
| STEP/DIR参数转换未校验 | `MOTOR_Control`把负数、NaN、无穷或超范围角度直接转成无符号脉冲数，可能产生未定义行为或错误运动 | 转换前检查有限的0～360°及方向0/1；非法输入不改变GPIO；注明该接口为主循环阻塞接口 |

## 根据用户无位移反馈新增只读诊断

用户截图显示目标位置3268、实际位置4、位移0、相电流17mA、总线电压11490mV，运动指令被接受但没有观察到实际位移。为区分校准、闭环参数、输出限制和硬件连接等原因，增加Watch request=13～16，分别读取3B健康/校准/保护状态、21 Emm PID、42 Emm驱动配置和23积分限幅；操作步骤见调试说明。

- 扩展`EMM_V5_BuildRead`，42查询使用4字节`Addr 42 6C 6B`；其他新增查询仍为3字节。
- PID和驱动配置有Emm专用格式，发送前必须已取得同地址有效Emm选项；未确认时拒绝发送。
- 扩展解析窗口与原始回复缓冲至33字节；校验42回复的长度、参数个数，解析微步、使能电平、电流与输出限制等字段。
- 保留`max_output_raw`原值，避免采用手册不同章节中相互矛盾的电压倍数。配置例帧`0B80`按2944正确解析，未照搬其旁注3000；3000对应`0BB8`。
- 新增测试覆盖3B各标志、15字节PID分包、33字节配置分包（包括每轮只读32字节）、内嵌ACK形状载荷、256细分、错误X配置头、跨地址缓存失效与Emm格式前置检查。
- 全部主机测试与768组厂家对比通过；ARM Debug与Release编译通过，无警告。新增诊断后的Debug FLASH为28532字节、RAM为3320字节；Release FLASH为15304字节、RAM为3312字节。

这次增加的是诊断能力，尚未确定不转的具体原因；未写电机参数、未触发校准、未烧录或操作实际电机。
