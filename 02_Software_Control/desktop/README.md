# 电机控制台

支持 macOS 和 Windows，使用 Python 3.10 及以上版本和 Tkinter。

## 在 VS Code 中运行项目

按 F5，选择 **运行项目：固件 + 桌面端**。统一入口 `run.py` 会构建 Debug 固件，通过 ST-Link 下载、校验并从 `0x08000000` 启动，再打开桌面端并选好调试器。桌面端打开后点击“连接”，再操作电机。

也可在工程根目录执行：

```sh
python3 run.py
```

Windows 使用 `py -3 run.py`。入口会自动寻找带 Tkinter 的 Python。固件工具从 PATH 或 STM32CubeCLT 安装目录查找。

仅查看界面时选择 F5 的 **运行桌面端：模拟**，或执行 `python3 run.py --simulate`。`--desktop-only` 会只打开 ST-Link 模式的桌面端；`--dry-run` 打印完整执行计划而不构建、下载或连接。多只 ST-Link 时用 `--probe 序列号` 指定设备。

## 启动

安装带 Tkinter 的 Python。模拟连接无需额外依赖；串口连接先安装串口依赖。

macOS：

```sh
python3 -m pip install -r desktop/requirements.txt
python3 -m desktop.app
```

也可以双击 `启动电机控制台.command`。脚本会寻找带 Tkinter 的 Python，包括 Homebrew、python.org、项目 `.venv` 和 `desktop/.runtime/venv`，不依赖 Finder 的 PATH。

Homebrew Python 若报 `No module named '_tkinter'`，安装与 Python 版本匹配的 Tk 支持。以 Python 3.14 为例：

```sh
brew install python-tk@3.14
```

可先检查启动环境：

```sh
./desktop/启动电机控制台.command --check
```

程序异常退出时，启动日志保存在 `desktop/.runtime/startup.log`。

Windows：

```powershell
py -3 -m pip install -r desktop/requirements.txt
py -3 -m desktop.app
```

也可以双击 `启动电机控制台.bat`。

以上命令在工程根目录运行。

## 连接

- **模拟连接**：本地模拟运动，适合查看界面和调试操作流程。
- **ST-Link 连接**：沿用 VS Code 下载/调试使用的 ST-Link，经 SWD 操作现有 F407 固件的 Watch 请求接口。选择调试器和对应的固件 ELF，再连接。电脑需安装 STM32CubeCLT，或在 PATH 中提供 `STM32_Programmer_CLI`、`arm-none-eabi-gdb` 和 `arm-none-eabi-objcopy`。默认 ELF 为 `build/Debug/02_MOTORCONTROL.elf`，可点“选择固件 ELF”更换。连接前核对板上 Flash 与 ELF 是否一致。
- **串口连接**：电脑通过自动收发的 USB-RS485 转换器直连 Emm 电机，选择串口、波特率、电机地址和每圈输入脉冲，再点击连接。默认 115200、地址 1、3200 脉冲/圈；按电机实际参数填写。

窗口上方始终显示“连接串口”栏。使用串口时选择“串口连接”，再从下拉列表中选择串口；列表显示完整路径、设备名称以及 USB / 系统串口分类。macOS 通常为 `/dev/cu.usbserial-*` 或 `/dev/cu.usbmodem*`，Windows 为 `COM*`。

未连接时每 2 秒刷新，也可点击“刷新串口”。只发现一个 USB 串口时自动选中；多个 USB 串口需要手动选择。蓝牙和调试系统串口不自动选中。可手动输入路径；断开后可以修改连接方式及参数。

ST-Link 是 USB 调试器，不一定提供串口。ST-Link 模式按序列号列出调试器，无需寻找 `/dev/cu.*` 或 `COM*`。板上的应用需运行到主循环；仅下载成功或停在断点时，固件不能处理桌面端请求。使用桌面端时结束 VS Code 的调试会话，以释放调试器。若提示 MCU 处于系统 Bootloader，检查 BOOT0 为低电平并复位，使固件从主 Flash 启动。

若提示“未发现 USB 串口”，先把 USB-RS485 转换器接入电脑；可通过拔插前后的列表变化确认对应接口。

## 操作

连接后点击“使能电机”。角度定位支持顺时针/逆时针单步、指定累计角度、就近回零及保存开机零点。按当前电机的实际方向，顺时针对应角度减小，逆时针对应角度增大；连续旋转设置方向、转速和时长，解锁后启动。停止按钮和 Esc 可结束运动。

两种实机连接的连续旋转按 `转速 × 6 × 时长` 换算为有限脉冲行程，使用现有 FD 定位指令；电脑计时到期也会发送停止。剩余时间由电脑计时，转速由位置反馈估算。连接时只查询，不自动使能。操作结果查看右侧信息及日志。运动结束后会短暂显示“确认到位中”，补读最终反馈后返回待机；操作日志同时保存在 `desktop/.runtime/operations.log`。

通信边界、停止语义和未验证事项见 [防御性说明](防御性说明.md)。

## 固定开机零点

“保存为开机零点”将轴的当前物理位置存入驱动器，并启用上电单圈就近回零，回零速度为 5 RPM。保存成功后当前坐标清零；以后电机重新上电会回到此位置，不依赖电脑或桌面端在线。

平时无需重复保存。以后要修改时，将轴移到新的位置、停稳后，再点击一次“保存为开机零点”。打开桌面端、连接设备和运行 F5 都不会重写原点。模拟连接中的保存只影响模拟坐标。

## 双电机与扇扫 / 俯仰

新版连接固定访问同一 RS485 总线上的 **ID 1（左轴）和 ID 2（右轴）**。两台驱动器须使用相同波特率、Emm 闭环模式和相同每圈输入脉冲（默认 3200）。串口模式只打开一次串口；ST-Link 模式使用新增的独占总线邮箱，需要先构建并烧录本版固件，旧版 ELF 不支持此功能。

窗口提供两个独立入口：**单电机控制**和**双电机 · 扇扫 / 俯仰**。

- 单电机控制：先选择 ID 1 或 ID 2，再使能所选电机。角度定位页修改“运动转速”后，在点动框填写“每次步长”并点击方向，或在定位框填写“目标累计角度”并点击“执行定位”；连续旋转页设置方向、转速、运行时间，解锁后启动。这些动作只控制选中的电机。
- 双电机控制：始终同时控制 ID 1 和 ID 2，与单轴选择无关。目标定位、往复扫描、标定 / 实验范围分别放在子页面。

双电机使用步骤：

1. 用单电机控制把机构调整到实际机械中心。进入双电机区，点击“使能两台电机”。
2. 在“标定 / 实验范围”核对左右轴方向，点击“标定机械中心”。只记录当前会话的中心，不写入开机原点；重新连接或保存单轴零点后需重新标定。
3. 在“目标定位”填写目标扇扫 α、目标俯仰 β、定位转速，再点击“执行双电机定位”。修改输入不会立即运动。纯扇扫设 β=0、修改 α；纯俯仰设 α=0、修改 β。界面预览标定方向映射前的中心相对电机命令 `q左=α+β`、`q右=α−β`，实际发给驱动器时还会应用标定中心和方向。两轴缓存 FD 目标后广播 `00 FF 66 6B` 同时启动；组合变化仍分段调整 α、β。
4. 在“往复扫描”选择扫描方向，填写往复半幅、另一方向的固定角度、次数和本页独立的转速，再点击“开始双电机往复扫描”。一次往复是负端→正端→负端，全部结束后扫描轴归中。切换扫描方向时，“固定扇扫 α / 固定俯仰 β”标签会随之变化。
5. ±25°、±5°只是资料中的工况示例，**不作为程序的机械极限**。默认不启用软件限位，也不预填任何已测极限。实测后可在“标定 / 实验范围”填写 α、β 的对称软件限位，勾选启用并点击“应用实验范围设置”。设置只有应用后生效，可取消勾选并再次应用以关闭；目标定位和往复扫描都遵守已应用的范围。角度输入保留通用数值边界以排除无效值，这不代表机构可达范围。

α/β 是电机共同/差动命令角，反馈同样是命令坐标；探头实际输出角及机械范围须通过实验测量。双电机默认转速为 1 RPM，转速输入沿用驱动协议范围，不再固定为 1～4 RPM。

右侧反馈随入口切换：单电机区显示所选电机详情，双电机区同时显示两轴当前位置、目标和状态。停止按钮 / Esc、断开连接、通信错误都会尝试停止 ID 1 和 ID 2；一台停止失败仍会尝试另一台。切换单/双电机入口会取消待执行的扫描段并请求停止，避免跨入口继续执行。板上 K0 停止两轴；桌面会话中 K1/K2 不执行单轴点动。

ST-Link 桌面会话独占固件 RS485，原 Watch 单轴状态机暂停；不要同时写原 Watch 邮箱。固件在 10 秒未收到新的桌面总线请求时尝试停止两台电机并结束会话。ST-Link 通过外部工具交换数据，反馈与停止有通信延迟，往复扫描到位后的停留时间也受此影响；USB-RS485 更适合连续扫描。断开线缆时软件停止能否送达取决于实际通信链路。

协议已核对本机厂家 `STM32F407_串口通讯__多机同步控制.rar` 中的 `Emm_V5_Pos_Control` 和 `Emm_V5_Synchronous_motion`。自动测试使用模拟总线，没有自动运行实机、修改 ID 或重写原点。

## 双轴总线错误 6 / UART 帧错误

`RS485_HW_ERROR=6` 表示 F407 的串口/DMA 驱动发生故障，并不等同于电机堵转。本次实机只读检查记录了 `RS485_STATE_FAULT=3`、`HAL ErrorCode=0x04`；按本工程 HAL 定义，`0x04` 是 **FE 帧错误**。报错前日志显示双轴扫描已经启动，随后通信退出。帧错误可能来自共线回报冲突，也可能来自接线、电平或干扰；仅凭错误码无法区分。

厂家同步例程提示不要让多台电机同时主动返回到位报文，否则可能发生总线冲突。本控制台采用逐地址查询状态、实际位置和轨迹位置来确认到位，双轴扫描要求**两台驱动器的 Response 都设为 Receive**。Reached/Both/Other 都会产生主动完成回报，None 不提供控制应答，也不适用于当前流程。启动双轴运动前会读取两台的 Emm 配置（`42 6C`，33 字节，Response 在第 23 字节），不符合时拒绝发送两轴 FD 定位命令；软件不会自动修改或保存驱动配置。

故障后先确认机构停稳，把两台电机的小屏幕 Response 设置为 Receive，核对 RS485 A/B、公共地和接线，再复位 F407、重新连接并重新标定中心。复位控制板不等于电机已停止，也不要通过电机断电重启来代替确认停稳，因为已配置的开机回零可能触发运动。

新版固件会将底层 HAL 错误、停止请求失败位图提供给桌面端；错误信息包含电机地址、命令和 FE/NE/ORE 等具体标志。停止/释放总线在故障下会分别尝试两台并在有限时间内退出，不再无限等待，也不会自动清除 UART 故障或续跑。发送停止成功只说明提交了命令，不代表已确认机械停稳。离线后不再把最后一次 α/β 数值显示成实时反馈。

本次修复涉及固件邮箱布局，需重新构建并烧录对应 Debug 固件；仅重启旧固件上的桌面端不足以更新。实机诊断仅进行了 ST-Link HOTPLUG 内存读取，未自动下发运动、重写 Response、复位或烧录。

## 响应速度与操作进度

本版优先使用持久 ST-Link 连接，避免每帧反复启动 CubeProgrammer。安装更新后的依赖后，通过原启动入口重新打开即可使用；已运行旧进程需退出后重启。未安装 pyOCD 时会明确显示“兼容模式”。依赖安装命令仍是 `python -m pip install -r desktop/requirements.txt`。

界面显示连接/校验阶段、处理耗时、定位反馈进度和扫描段数；右侧“下一步”说明当前可操作步骤。状态和位置优先更新，电压/电流是最近一次低频读取值。已有上一版故障修复固件时，本次不需重新烧录。

实测范围与实现说明见 [桌面端性能优化与交互说明](../docs/桌面端性能优化与交互说明.md)。

## 连续旋转结束附近的状态查询超时修复

2026-11-27 的操作日志记录：17:07:29 启动 5 RPM、10 秒连续旋转，17:07:41 报 `3A` 状态查询超时。故障后只读检查显示 F407 的驱动为 READY、HAL 错误为 0，两轴退出停止请求均已提交；与此前 FE 帧错误不同。原始故障当时未记录原始 RX，因此无法仅凭日志证明具体丢包原因。

已修复持续 SWD 读取中的一致性缺口：运行中的 MCU 可能在主机依次读取 `rx_len` 和 `result` 之间完成回复，造成完成标志与长度不属于同一时刻。桌面端现在对已完成的回复复核 24 字节头部，头部变化则重取快照，避免把不完整读取当成无回复；尚在处理中的邮箱不会为此增加第二次读取。

对明确的只读查询，超时后仅允许一次补读；FD 定位、使能、停止、保存参数等有副作用的指令一律不自动重发。连续读取失败仍进入原停止/故障流程，已有停止请求排队时优先让出轮询。超时诊断另存到 `desktop/.runtime/communication_errors.jsonl`，包含电机 ID、功能码、收到的原始字节及最近的总线快照。

验证包含：连续旋转计时结束后丢失一次状态回复仍保持连接、持续缺失最多查询两次、运动应答缺失不重发、跨完成时刻的快照读取。104 项桌面回归通过。实机仅进行状态/位置读取验证，30.06 秒完成 1184 次查询，无状态超时、无 HAL 错误；退出按原协议提交停止，未发送使能或运动指令。未进行实机连续旋转复测。固件代码及邮箱布局未变更，此修复只需重启桌面端。

## 单电机就近回零

单电机页的“就近回零”选择距离当前角度最近的等效零位，每圈为 360°，目标相对位移不超过半圈。例如累计 730°→720°，只反转约 10°；350°→360°，只正转约 10°；−730°→−720°，只正转约 10°。恰好相差 180°时，选择累计角度绝对值较小的一侧。

只作用于当前选中的电机，速度使用本页“运动转速”，仍要求连接、使能、停稳。软件保留累计圈数及保存的开机原点，不通过清零坐标或重写原点伪造回零。右侧主读数显示单圈角度（0～360°），下方同时显示累计角度，所以就近回零后可以看到单圈为 0°、累计为 720°。实机反馈精度受编码器与输入脉冲分辨率影响。

若确实需要把全部圈数退回累计 0°，在“目标累计角度”输入 0，点击“执行定位”。双电机的“双轴回到中心”仍返回已标定的机械中心，不做逐轴取模；它与单电机就近回零是两个操作。上电回零配置不变，无需为本次改动重新烧录固件或重存零点。
