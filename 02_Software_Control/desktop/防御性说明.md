# 桌面端防御性说明

## 连接与总线

串口连接使用 USB-RS485 直连 Emm 电机，协议编码依据工程 `Core/BSP/emm_v5.c` 和 `zdt_x42s.c`。当前 STM32F407 固件没有提供电脑命令入口，ST-Link 虚拟串口不能直接用于此桌面端。直连时应断开 F407 的 RS485 主机连接，避免两个主机同时发送。

每圈脉冲默认 3200 仅对应常见 1.8°、16 细分配置，必须与实际配置一致。输入脉冲换算与反馈 65536 单位/圈分开处理。定位前核对 Emm、闭环及输入缩放选项。目标按整脉冲量化，界面在命令接受后显示量化目标。

## 运动与停止

连接不自动使能、不发送运动。连接时若设备已经使能，界面按真实状态显示。连续启动需要选方向并解锁，修改参数、切换模式、停止、失能和断开会撤销解锁。忙时不接受第二条运动。

连续旋转采用有限位置行程，不使用尚未在工程中核对的速度模式命令。电脑到时发送 FE，但串口事务及系统调度可能带来延迟，电脑计时不能替代设备端看门狗。进程异常退出、串口断开时不能保证停止；有限行程仍可能继续执行。

停止确认仅表示 FE 被接受。界面随后至少观察 0.6 秒位置稳定才回到待机；这只是采样证据，不能代替硬件急停或证明机械绝对静止。关闭或通信异常时后台线程尝试停止并释放串口，失败时不能保证电机停止。位置超时不自动重发运动。

“返回 0°”使用当前驱动/用户坐标进行定位。“保存为开机零点”会明确写入驱动的单圈原点及上电回零配置，属于持久化操作。

## 反馈与故障

模拟模式只显示模拟位置及速度，电压电流留空。真实模式显示查询所得位置、电压、电流；转速由相邻位置采样估算，非驱动直接返回的速度。

定位完成同时核对到位位、轨迹设定位置及实际位置。超时、拒绝、堵转或串口异常会结束连接并记录原因，断开后读数显示为空。握手失败不会退回模拟连接。

协议采用固定 6B 帧尾，没有 CRC 和事务序号。适配器按固定长度解析、过滤无关功能码，失败后关闭串口；新连接无法可靠区分未来到达的旧回复。实际线缆、转换器延迟、驱动回复设置仍需实机检查。

## 验证范围

单元测试使用模拟后端及伪串口，覆盖报文、连接切换、坐标换算、停止和错误处理。跨平台代码与启动脚本不等同于两种系统及真实电机均已现场验证，实际验证结果应以交付记录为准。

## ST-Link 连接

ST-Link 模式通过 STM32CubeProgrammer CLI 的 HOTPLUG 模式读写运行中 SRAM；不发复位、暂停、继续运行、下载或擦除命令。模式语义依据 [ST 官方 CLI 文档](https://dev.st.com/stm32cube-docs/prog/2.23.0/en/docs/markup/CubeProg_Command_Lines.html)。固件控制仍由原 `MOTOR_App` 调度者执行，桌面端不直接争用 MCU 的 RS485。

从所选 ELF 的 DWARF 动态解析 `main.c` 中 `s_debug` 字段地址及大小，兼容编译器短枚举布局。先只读比较 ELF 的 Flash 镜像与板上内容，通过后才允许写请求。邮箱参数限制在解析出的 SRAM 字段内，最后写 request；运动使用原有一次性 arm 和 request=6，停止用 request=10。初始化数据异常、邮箱忙、固件拒绝或操作失败时结束连接，不恢复固件锁定状态。

连接时只提交状态、位置、电压及电流查询，不提交使能或运动。ST-Link 的正常下载/调试不代表固件已在运行，也不代表它提供虚拟串口。请先运行固件到主循环并结束 VS Code 调试会话，避免两个工具争用 ST-Link 或同时写 Watch 请求。

调试快照没有原子版本号；读到的是固件定期发布的数据，存在采样延迟。CubeProgrammer 进程启动及 SWD 连接也会增加延迟，ST-Link 模式适合台架调试，不适合要求硬实时停止的场景。电脑端限时仍不能替代 MCU 端看门狗。停止时等待位置采样稳定，不能证明绝对静止。

当前固件未启用 `USER_VECT_TAB_ADDRESS`，因此 `VTOR=0` 可以是正常的 Flash 启动映射。桌面端会比较地址 0 与 `0x08000000` 的初始栈指针和复位入口；两者一致且位于有效应用范围时允许连接。系统存储器启动仍会被区分并拒绝，F407 的系统存储器地址见 [ST AN2606](https://www.st.com/resource/en/application_note/an2606-stm32-microcontroller-system-memory-boot-mode-stmicroelectronics.pdf)。

固件主循环会立即清除 `request`。CubeProgrammer 的数值写入默认回读校验可能因此误报失败；请求字写入末尾追加 `-nv`，避免对这个瞬时值做回读校验，再通过固件的接受/拒绝计数确认请求结果。其他参数的校验与 Flash 镜像匹配检查保留。

本轮已通过实机 ST-Link 连接，并读取到位置 `-0.005493°`、电压 `11.567 V`、电流 `0.016 A`。验证仅提交状态、位置、电压和电流读取请求，没有发送使能、运动、复位或下载。电机使能状态按设备原有反馈显示，不由连接自动改变。

## 统一运行入口

`run.py` 默认执行构建、下载、校验、启动应用和打开桌面端，VS Code 的“运行项目：固件 + 桌面端”调用此入口。下载阶段使用 `mode=UR` 和 `-w/-v/-g 0x08000000`，会修改板上 Flash 并启动应用；与桌面端连接时的 HOTPLUG 只读校验分开。该流程不通过 GDB 保持调试会话，下载工具退出后将 ST-Link 留给桌面端。

运行阶段未启动任何电机运动、未自动使能或自动连接。仅一个 ST-Link 时使用其序列号；多个调试器需要显式指定 `--probe`。构建或下载失败时返回错误，不继续打开桌面端。`--simulate`、`--desktop-only` 和 `--dry-run` 均不下载固件。

从主 Flash 地址显式启动应用不修改 BOOT0 接线；后续断电启动仍取决于板上的启动配置。本次验证完成固件构建与使用测试替身的调用顺序检查，没有实际执行自动下载流程。

## 请求接收竞态修复与验证

主循环读取 `s_debug.request` 后，仅在读到非零请求时清除。若每轮无条件写零，SWD 恰好在读取与清除之间发布的新请求可能被覆盖，表现为邮箱已空但接受/拒绝计数均未变化。桌面端超时信息现区分“邮箱已清空但未获确认”和“请求尚未被主循环取走”，不自动重发运动。

修复后的固件已构建、校验并下载到本机所连的 F407。持续 ST-Link 连接验证运行 90.1 秒，58 次反馈查询获得确认、无拒绝或超时；验证只读取状态、位置、电压、电流，没有发送使能或运动。60 项桌面回归测试及新增 2 项超时诊断测试通过。C 主机测试在保留 UBSan 的条件下通过；本机 ASan 运行库卡在初始化阶段，未完成 ASan 检查。

## 单步完成后的反馈确认

STM32 可能已结束运动流程，而桌面端最近一次位置快照仍来自运动中，甚至位置/状态有效标志正处于查询失效期。桌面端现在保留本次完成通知，进入“确认到位中”，依次补读状态和实际位置，再判断最终位置；确认期间禁止第二条运动，不重发原来的 FD 命令。

若补读后仍存在位置偏差，继续读取反馈，最多等待 15 秒。未确认到位时记录目标、实际位置和固件快照，提交一次停止请求，保留 ST-Link 连接并显示“位置反馈异常”；不会将电机位置异常直接伪装成 USB 断开。通信工具本身失败仍按连接故障处理。停止按钮可以继续使用。

操作日志持久化到 `desktop/.runtime/operations.log`；最终位置确认异常的固件快照保存在 `desktop/.runtime/motion_errors.jsonl`。回归测试覆盖 10° 对应 89 输入脉冲、完成通知先于反馈、有效但陈旧的位置缓存，以及最终位置偏差不重发运动且保留连接。此修复验证使用伪设备，没有为复现而追加实机运动。

## 固定开机原点保存

依据 [厂家 Emm 原点回零协议](https://devpress.csdn.net/xian/68945b69080e555a88d61cd3.html)，读取 `22` 参数后依次执行 `93 88 01`（持久保存当前物理原点）、`0A 6D`（清当前坐标）、`4C AE 01`（持久保存回零参数），最后再次读取 `22` 并逐字节比较。回零模式为单圈就近、速度 5 RPM、超时 10000 ms、上电自动回零开启。碰撞检测阈值及方向等其他字段从原参数复制，保持原值。

驱动在 NVM 保存确认后仍可能忙碌，因此保存原点后和保存配置后留出 250 ms 间隔；持久写入应答期限延长为 1000 ms。实机首次保存时原点确认成功，但紧接的清坐标命令因间隔过短超时；调整间隔后整个保存及读回均成功。该过程没有发送 `9A` 回零或 `FD` 运动命令。

F407 新增 request=19 只读回零参数，request=20 为显式保存流程，后者要求一次性 arm=`0x484F4D45`。固件启动、F5 下载、普通连接都不自动重存原点。保存前确认驱动就绪、无回零，并读取两次位置确认轴已稳定在一个输入脉冲的范围内。保存为多条驱动事务，若中途失败，部分原点参数可能已生效；不会自动重试持久写入。

本次已保存的原位置反馈为 16833 编码器单位（约 92.4664° 的旧坐标）；保存后反馈为 0，驱动读回 mode=0、power_on=1、speed=5、timeout=10000。保存记录位于 `desktop/.runtime/startup_origin_saved.json`，原回零参数备份位于 `desktop/.runtime/homing_config_before.json`。尚未对电机电源执行断电重上电验证。

该零点属于单圈物理方向，不能区分机械机构相差整圈的多圈位置。以后开启电机电源即可能自动运动回零，这是已启用的驱动行为；与 F407 是否运行或桌面端是否连接无关。
